รายการงานฝั่ง Backend และ Web

ระบบ ClinicCare Scale — คิวออนไลน์ A และ Walk-in B

เอกสารส่งมอบงานระหว่างทีม

วันที่จัดทำ: 16 กันยายน 2569
Device ทดสอบ: SCALE-001
สถานะ Firmware: Queue A และ Walk-in ผ่าน Software End-to-End แล้ว
ขอบเขตเอกสาร: งานที่ Backend/Web ทำได้ทันที และงานที่ต้องรอข้อมูลจากทีม Firmware/Hardware

ข้อสรุป: ทีม Backend และ Web สามารถทำงานหลักต่อได้ทันทีโดยไม่ต้องรอเซนเซอร์จริง งานเร่งด่วนที่สุดคือแก้ Print Outbox ไม่ให้ส่งงานเดิมวนหลังได้รับ failed, ยืนยัน idempotency ของ Measurement และทำให้สถานะ OTP/Print บนเว็บตรวจสอบได้ชัดเจน

1. สถานะที่ Firmware ส่งมอบแล้ว

  • เชื่อม MQTT/TLS พอร์ต 8883, MQTT 3.1.1, QoS 1 และ Retain false
  • รองรับ Queue A: OTP → Session → Measurement → ACK → Print → Print ACK
  • รองรับ Walk-in B โดยไม่ใช้ OTP
  • สร้าง request_id/message_id ใหม่ และ Retry ด้วย message_id/payload เดิม
  • เก็บ Measurement Pending ใน NVS และส่งใหม่หลัง reconnect/restart
  • ตรวจ request_id, message_id, measurement_id และ Queue prefix A/B
  • รับ expires_at, ตรวจ Session หมดอายุ และส่งเวลา measured_at แบบ UTC
  • ไม่คำนวณ BMI; Backend เป็นผู้คำนวณและส่งมากับ Print Job
  • ป้องกัน Print Job ซ้ำด้วย print_job_id และเก็บประวัติใน NVS
ผลทดสอบจริง: Queue A ได้ A002, Measurement 67/68, BMI 20.76 และการจำลอง ACK สูญหายได้รับ duplicate พร้อม Measurement/Queue เดิม ส่วน Walk-in ได้คิว B และผ่าน Retry/NVS/Duplicate แล้ว

2. งาน Backend

ลำดับความสำคัญงานเริ่มได้
BE-01P0แก้ Print Outbox ไม่ให้ส่ง print_job_id เดิมวนไม่สิ้นสุดหลังได้รับ status=failedทำได้ทันที
BE-02P0กำหนด Print retry policy: backoff, max attempts, terminal state และ manual reprintทำได้ทันที
BE-03P0เมื่อ measurement ACK ระบุ print_pending=true ต้องมี Print Job ใน Outbox จริงและส่งได้ทำได้ทันที
BE-04P0บังคับ Unique/Idempotency ด้วย device_id + message_id; duplicate ต้องคืน Measurement และ Queue เดิมทำได้ทันที
BE-05P0Measurement ACK แบบ accepted/duplicate ต้องมี message_id, measurement_id > 0, queue_number และ print_pendingทำได้ทันที
BE-06P1ตรวจ queue_number ใน otp-result ให้ตรงกับ measurement-ack ของ Session เดียวกันทำได้ทันที
BE-07P1แยก OTP error เช่น OTP_EXPIRED, OTP_USED, OTP_NOT_ACTIVE_YET, OTP_NOT_FOUND และ RATE_LIMITEDทำได้ทันที
BE-08P1เก็บ Audit Log ตาม request_id, measurement_session_id, message_id และ print_job_idทำได้ทันที
BE-09P1ตรวจ Print ACK: printed/failed พร้อม error_code และเวลา received_atทำได้ทันที
BE-10P1สร้าง print_job_id ใหม่เฉพาะเมื่อผู้ใช้สั่งพิมพ์ใหม่ ห้ามใช้ ID เดิมเป็นงานใหม่ทำได้ทันที
BE-11P1เพิ่ม Health/Metric สำหรับ MQTT consumer, Outbox backlog, ACK latency และ failure rateทำได้ทันที
BE-12P1กำหนด MQTT ACL และ Credential แยกต่อ Device; ห้าม Client เข้าถึง Topic ของเครื่องอื่นทำได้ทันที
BE-13P2รองรับ PAPER_OUT หรือ error เฉพาะ Printer เพิ่มเติมรอผล Hardware

3. งาน Web/Admin

ลำดับความสำคัญงานเริ่มได้
WEB-01P0แสดง Queue A/B และ Measurement ล่าสุดโดยไม่สร้างแถวซ้ำเมื่อ Backend deduplicateทำได้ทันที
WEB-02P0แสดง Weight, Height และ BMI จาก Backend พร้อมหน่วยที่ถูกต้องทำได้ทันที
WEB-03P1แสดง OTP status: พร้อมใช้, ยังไม่ถึงเวลา, หมดอายุ, ใช้แล้ว และปุ่มส่งรหัสใหม่ทำได้ทันที
WEB-04P1แสดง Device Online/Offline และเวลาที่ได้รับข้อมูลล่าสุดทำได้ทันที
WEB-05P1แสดง Print status: pending, printed, failed และ error_code ที่อ่านเข้าใจได้ทำได้ทันที
WEB-06P1ปุ่ม Reprint ต้องเรียก Backend ให้สร้าง print_job_id ใหม่และเก็บผู้สั่ง/เวลาทำได้ทันที
WEB-07P1เพิ่ม Real-time update หรือ Polling พร้อมสถานะเมื่อการอัปเดตขาดหายทำได้ทันที
WEB-08P2หน้าตรวจสอบ Timeline ของ OTP → Measurement → Print สำหรับผู้ดูแลทำได้ทันที
WEB-09P2ข้อความช่วยเหลือตาม Error จากอุปกรณ์ เช่นตรวจสาย Printer หรือเติมกระดาษบางส่วนรอ Hardware

4. Contract ที่ต้องรักษา

Measurement ACK สำเร็จ

{
  "message_id": "MSG-A-or-B-...",
  "status": "accepted",
  "measurement_id": 68,
  "queue_number": "A002",
  "print_pending": true
}

Measurement เดิมถูกส่งซ้ำ

{
  "message_id": "MSG-A-or-B-เดิม",
  "status": "duplicate",
  "measurement_id": 68,
  "queue_number": "A002",
  "print_pending": true
}

ห้ามสร้าง Measurement หรือ Queue ใหม่เมื่อ device_id + message_id เดิมถูกส่งซ้ำ

Print ACK

{
  "print_job_id": "PRINT-...",
  "device_id": "SCALE-001",
  "status": "failed",
  "error_code": "PRINTER_NOT_CONNECTED"
}

5. เกณฑ์รับงาน Backend

  • ☐ ส่ง Measurement ใหม่ครั้งแรก ได้ accepted และ Measurement/Queue หนึ่งรายการ
  • ☐ ส่ง message_id และ payload เดิมซ้ำ ได้ duplicate พร้อม ID/Queue เดิม
  • ☐ message_id เดิมแต่ payload ต่างกัน ต้อง rejected ด้วย MESSAGE_ID_CONFLICT
  • ☐ OTP ถูกวันและยังไม่ใช้ ได้ accepted พร้อม Session/Queue/expires_at
  • ☐ OTP ใช้แล้ว/หมดอายุ/ยังไม่ถึงเวลา ได้ error ที่แยกสาเหตุได้
  • ☐ print_pending=true แล้วมี Print Job จริง
  • ☐ รับ print-ack=failed แล้ว Outbox หยุดตามนโยบาย ไม่ส่งวนถี่ไม่สิ้นสุด
  • ☐ Manual reprint สร้าง print_job_id ใหม่
  • ☐ Log สามารถค้นเส้นทางครบด้วย request/message/print job ID

6. เกณฑ์รับงาน Web

  • ☐ Queue A/B แสดงเพียงหนึ่งแถวต่อคิว
  • ☐ Weight/Height/BMI ตรงกับข้อมูล Backend
  • ☐ สถานะ OTP และวันเวลาที่ใช้ได้แสดงชัดเจน
  • ☐ สถานะ Printer เปลี่ยนตาม Print ACK
  • ☐ Reprint ไม่ใช้ print_job_id เดิม
  • ☐ ผู้ดูแลเห็น Device Online/Offline และ Last seen
  • ☐ หน้าเว็บแจ้งเมื่อ Real-time update ขาดการเชื่อมต่อ

7. สิ่งที่ต้องรอจาก Firmware/Hardware

ข้อมูลที่รอผู้ส่งมอบใช้กับงาน
ค่าคาลิเบรต Load Cell และช่วงค่าจริงFirmware/HardwareValidation/ข้อความบนเว็บ
ความสูงติดตั้งและ Offset ของ VL53L1XFirmware/Hardwareทดสอบ Height จริง
Printer VID/PID/Endpoint ที่ยืนยันแล้วFirmware/HardwareProduction configuration
ความสามารถอ่าน PAPER_OUT/Status ของ PrinterFirmware/HardwareError code และ UI
รูปแบบบัตรคิวและภาษา/Encoding ที่พิมพ์ได้Product + HardwarePrint template
รายการ Device ID และ Credential ต่อสาขาOps + FirmwareMQTT ACL/Provisioning
ผลทดสอบ End-to-End กับคนและกระดาษจริงทุกทีมProduction sign-off
สิ่งที่ไม่ต้องรอ: Backend/Web ไม่ต้องรอ Load Cell, Height Sensor หรือ Printer เพื่อแก้ Idempotency, OTP state, Print Outbox, Web duplicate, Logging, Monitoring และ MQTT ACL เพราะ Firmware ส่งค่าจำลองและทดสอบ Contract ได้แล้ว

8. ข้อความสรุปส่งทีม

Firmware Queue A และ Walk-in ผ่าน Software End-to-End แล้ว กรุณาดำเนินการ BE-01 ถึง BE-05 และ WEB-01 ถึง WEB-02 เป็นลำดับแรก โดยเฉพาะ Print Outbox, idempotency และความสัมพันธ์ระหว่าง print_pending กับ Print Job งานเหล่านี้ไม่ต้องรออุปกรณ์จริง ส่วน PAPER_OUT, Printer status เฉพาะรุ่น และรูปแบบบัตรจริงให้รอผลจากทีม Firmware/Hardware
