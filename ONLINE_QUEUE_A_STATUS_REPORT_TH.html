1. ลำดับการทำงาน

  1. ผู้ป่วยมีการจองที่อนุมัติแล้วและได้รับ OTP สำหรับวันนัด
  2. ESP32 ส่ง OTP ไปยัง /otp-verify พร้อม request_id ใหม่
  3. Backend ตอบ /otp-result พร้อม Session, หมายเลขคิว A และเวลาหมดอายุ
  4. ESP32 ตรวจ Session/เวลา/คิว แล้วส่งน้ำหนักและส่วนสูงไปยัง /measurements
  5. Backend บันทึกค่า คำนวณ BMI และตอบ /measurement-ack
  6. Backend ส่ง /print; ESP32 พิมพ์และตอบ /print-ack

2. MQTT Contract

ทิศทางTopicหน้าที่
ESP32 → Backend.../otp-verifyตรวจ OTP

3. ความสามารถและสถานะ

รายการสถานะรายละเอียด
ตรวจรูปแบบ OTPผ่านจริงต้องเป็นตัวเลข 6 หลัก
Correlation ของ OTPผ่านจริงรับเฉพาะ request_id ที่ตรงกับคำขอปัจจุบัน
OTP ถูกต้องผ่านจริงได้รับ accepted, Session และคิว A002
OTP ผิด/ผิดวัน/ใช้ซ้ำผ่านจริงBackend ตอบ INVALID_OTP และ Firmware ไม่ส่ง Measurement
Session expiryแก้และ Build ผ่านอ่าน expires_at และไม่ยอมวัดเมื่อ Session หมดอายุ
เวลา UTCผ่านจริงใช้ NTP และส่ง measured_at แบบ UTC
Measurement validationผ่านจริงน้ำหนัก 1–300 kg, ส่วนสูง 30–250 cm
Measurement ACKผ่านจริงตรวจ message_id, measurement_id และหมายเลขคิว A
คิวจาก OTP ตรงกับ ACKแก้และ Build ผ่านหากหมายเลขไม่ตรงจะเก็บ Pending และไม่ยอมรับ ACK
NVS Pendingผ่านพื้นฐานเก็บ payload/message_id ก่อนส่งและส่งใหม่หลัง reconnect
ACK สูญหาย/Duplicateผ่านจริงส่ง message_id เดิมและได้ duplicate พร้อม Measurement/Queue เดิม
Retry backoffแก้และ Build ผ่านหน่วง 10, 20, 40 และสูงสุด 60 วินาที
Print pending watchdogแก้และ Build ผ่านเตือนหาก print_pending=true แต่ไม่มี /print ภายใน 30 วินาที
รับ Print Jobผ่านจริงได้รับ Queue/W/H/BMI และตรวจ schema
กันพิมพ์ซ้ำผ่านจริงจำ print_job_id 16 รายการล่าสุดใน NVS
พิมพ์กระดาษจริงยังไม่ทดสอบไม่มี Printer จึงตอบ PRINTER_NOT_CONNECTED ตามปกติ

4. หลักฐานการทดสอบจริง

รอบปกติ

  • OTP accepted และได้ queue_number: A002
  • Backend บันทึก measurement_id: 67
  • หน้าเว็บแสดง Weight 60.00, Height 170.00 และ BMI 20.76
  • ได้รับ Print Job และตอบ failed / PRINTER_NOT_CONNECTED เพราะยังไม่มีเครื่องพิมพ์

รอบจำลอง Measurement ACK สูญหาย

  • Backend ตอบ accepted: measurement_id: 68, queue_number: A002
  • Firmware จงใจข้าม ACK แรกและเก็บ Pending
  • ครบ 10 วินาที Firmware ส่ง payload และ message_id เดิม
  • Backend ตอบ duplicate พร้อม Measurement 68 และ A002 เดิม
  • Firmware ล้าง Pending และกลับสถานะพร้อมเริ่ม
การทดสอบหลายรอบด้วย OTP ใหม่สามารถสร้าง Measurement ใหม่ในคิวเดิมได้ตามงานทดสอบ แต่ retry ของ Measurement เดิมต้องไม่สร้าง Measurement หรือคิวซ้ำ

5. การแก้ไข Firmware รอบล่าสุด

  • บังคับ ACK แบบ accepted/duplicate ต้องมี measurement_id > 0
  • อ่านและตรวจ expires_at; เพิ่มเวลารอ OTP จาก 15 เป็น 30 วินาที
  • เก็บคิวจาก OTP และตรวจว่าตรงกับคิวใน Measurement ACK
  • เพิ่ม retry backoff สูงสุด 60 วินาทีโดยไม่ลบ Pending
  • เพิ่มคำเตือนเมื่อ Backend ไม่ส่ง Print Job ภายใน 30 วินาที
  • ตั้ง Environment ปกติแบบไม่เปิดอุปกรณ์เป็นค่าเริ่มต้น
  • เพิ่ม Environment esp32-s3-online-retry-test สำหรับทดสอบเฉพาะกิจ
  • อัปโหลด Firmware ปกติกลับลง COM19 หลังจบทดสอบ

6. งานที่ยังเหลือ

เจ้าของงานรายการสถานะ
Backendหยุดหรือจำกัดการส่ง Print Job เดิมซ้ำหลังได้รับ failed; เพิ่ม retry/backoff/max attemptsต้องแก้อีกระบบ
Backendแยก OTP error เป็น OTP_EXPIRED, OTP_USED, OTP_NOT_ACTIVE_YET เพื่อวิเคราะห์ง่ายควรปรับ
Backend/DBยืนยัน unique constraint/idempotency ของ device_id + message_idต้องยืนยัน
Webยืนยันว่า retry message_id เดิมแสดงเพียงหนึ่ง Measurement และผูก A002 ถูกต้องต้องยืนยัน
Firmware Testทดสอบรีสตาร์ตระหว่างคิว A รอ Measurement ACK โดยเฉพาะยังไม่ทดสอบตรง
Hardwareคาลิเบรต HX711/Load Cell และกำหนดความสูงติดตั้ง VL53L1Xยังไม่ทำ
Hardwareทดสอบ Keypad, LCD, USB Printer และกระดาษจริงยังไม่ทำ
Security/Opsยืนยัน MQTT ACL, Credential แยกต่ออุปกรณ์, CA certificate และ Client ID ไม่ซ้ำก่อน Production
ขอบเขตความสำเร็จ: สถานะ ผ่าน ในรายงานนี้หมายถึง Software End-to-End โดยใช้ OTP จริงและค่าวัดจำลอง ไม่รวมความแม่นยำของเซนเซอร์หรือผลการพิมพ์กระดาษจริง
