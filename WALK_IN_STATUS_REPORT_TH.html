ClinicCare Scale — Firmware / MQTT / Backend Integration

Walk-in Core Software: ผ่านการทดสอบแล้ว

วันที่จัดทำ: 16 กันยายน 2569
อุปกรณ์ทดสอบ: ESP32-S3 / Device ID SCALE-001
ขอบเขต: ทดสอบระบบโดยยังไม่ต่อเซนเซอร์และเครื่องพิมพ์จริง

สรุปผู้บริหาร: Firmware สามารถสร้างข้อมูล Walk-in ส่งผ่าน MQTT/TLS ให้ Backend สร้างคิว B รับ ACK เก็บงานค้างใน NVS ส่งซ้ำหลังการเชื่อมต่อหรือรีสตาร์ต และป้องกันการสร้างคิวซ้ำด้วย message_id เดิมได้แล้ว ส่วนที่ยังต้องทำคือทดสอบอุปกรณ์จริงและปรับพฤติกรรม Print Outbox ของ Backend

1. ความสามารถที่พร้อมใช้งาน

รายการสถานะรายละเอียด
รับค่าวัดจำลองผ่านป้อนผ่าน Serial เช่น W 60 170
สร้างข้อมูล Walk-inผ่านสร้าง JSON โดยกำหนด mode: "walk_in"
เชื่อมต่อ MQTT/TLSผ่านพอร์ต 8883, MQTT 3.1.1, QoS 1 และ Retain false
ส่ง Measurementผ่านส่งไปยัง clinic/v1/devices/SCALE-001/measurements
Backend สร้างคิว Bผ่านได้รับคิว Walk-in เช่น B005, B007 และ B008
รับและตรวจสอบ ACKผ่านรองรับ accepted, duplicate และ rejected พร้อมตรวจ message_id
ตรวจประเภทหมายเลขคิวผ่านWalk-in ต้องได้รับ queue_number ที่ขึ้นต้นด้วย B
ป้องกันการวัดซ้อนผ่านไม่สร้างรายการใหม่ระหว่างที่ Measurement เดิมยังรอ ACK
บันทึก Pending ลง NVSผ่านข้อมูลค้างไม่หายเมื่อ Wi-Fi หลุดหรือบอร์ดรีสตาร์ต
Retry ด้วยข้อมูลเดิมผ่านส่ง payload และ message_id เดิมหลัง reconnect หรือ ACK สูญหาย
Backend Deduplicationผ่านBackend ตอบ duplicate และคืน measurement/queue เดิม ไม่สร้างคิวซ้ำ
รับงานพิมพ์ผ่าน*รับ Topic /print และป้องกันงานซ้ำด้วย print_job_id
ส่งผลการพิมพ์ผ่าน*ส่ง /print-ack ได้; เมื่อไม่มี Printer จะตอบ failed/PRINTER_NOT_CONNECTED

* ผ่านในระดับโปรโตคอล ยังไม่ได้ทดสอบการพิมพ์กระดาษจริง

2. MQTT Contract สำหรับ Walk-in

Firmware → Backend

Topic: clinic/v1/devices/SCALE-001/measurements

{
  "schema_version": "1.0",
  "message_id": "MSG-B-SCALE-001-xxxxxxxxxx-xxxxxxxx",
  "device_id": "SCALE-001",
  "mode": "walk_in",
  "measured_at": "2026-09-15T18:28:31.000Z",
  "weight": 60,
  "height": 170
}

Firmware ไม่คำนวณ BMI เอง โดย Backend เป็นผู้คำนวณและส่ง BMI กลับมากับ Print Job

Backend → Firmware: สร้างคิวสำเร็จ

Topic: clinic/v1/devices/SCALE-001/measurement-ack

{
  "message_id": "MSG-B-SCALE-001-xxxxxxxxxx-xxxxxxxx",
  "status": "accepted",
  "measurement_id": 66,
  "queue_number": "B008",
  "print_pending": true
}

Backend → Firmware: รับข้อมูลเดิมซ้ำ

{
  "message_id": "MSG-B-SCALE-001-xxxxxxxxxx-xxxxxxxx",
  "status": "duplicate",
  "measurement_id": 66,
  "queue_number": "B008",
  "print_pending": true
}

ACK แบบ duplicate ต้องคืน measurement_id และ queue_number เดิม โดยไม่สร้างคิวใหม่

3. หลักฐานการทดสอบ Reliability

  1. Firmware ส่ง Measurement และ Backend สร้างคิว B008 ด้วยสถานะ accepted
  2. Firmware จำลองว่า ACK ครั้งแรกสูญหาย และยังเก็บ Pending ไว้
  3. ครบเวลาจึงส่ง payload และ message_id เดิมอีกครั้ง
  4. Backend ตอบ duplicate พร้อม measurement_id 66 และคิว B008 เดิม
  5. ไม่เกิดคิวเพิ่ม และ Firmware ล้าง Pending กลับสู่สถานะพร้อมใช้งาน
  6. ทดสอบเพิ่มเติมโดยตัด Wi-Fi แล้วรีเซ็ตบอร์ด พบว่า NVS โหลด Measurement เดิมและส่งต่ออัตโนมัติหลังเชื่อมต่อสำเร็จ

4. สิ่งที่ยังต้องดำเนินการ

ผู้รับผิดชอบรายการสถานะ
Backend ตรวจ Print Outbox: บางครั้งส่ง print_job_id เดิมซ้ำหลังได้รับ failed ควรกำหนด terminal state หรือ retry/backoff/จำนวนครั้งสูงสุด ต้องตรวจ
Backend เมื่อ ACK ระบุ print_pending=true ต้องรับประกันว่ามีการสร้างและส่ง /print; เคยพบหนึ่งกรณีที่งานพิมพ์มาไม่สม่ำเสมอ ต้องตรวจ
Web ยืนยันว่าคิวทดสอบล่าสุด เช่น B008 แสดงเพียงหนึ่งรายการและสถานะอัปเดตถูกต้อง รอยืนยัน
Firmware/Hardware ทดสอบและปรับเทียบ HX711/Load Cell, VL53L1X, Keypad, LCD และ USB Printer ของจริง ยังไม่ทดสอบจริง
ทุกทีม ทดสอบ End-to-End ด้วยคนวัดจริง ตั้งแต่ชั่งน้ำหนักจนได้รับบัตรคิวที่พิมพ์ออกมา ขั้นถัดไป
หมายเหตุเกี่ยวกับ Printer: การได้รับ PRINTER_NOT_CONNECTED ขณะยังไม่ต่อเครื่องพิมพ์เป็นพฤติกรรมปกติ และไม่ใช่ความผิดพลาดของขั้นตอนสร้างคิว Walk-in

5. ข้อความส่งมอบให้อีกทีม

ระบบ Walk-in ส่วนหลักผ่านแล้ว Firmware สามารถส่งน้ำหนักและส่วนสูงผ่าน MQTT/TLS พอร์ต 8883 ด้วย QoS 1 และ Retain false จากนั้น Backend สร้างคิว B และตอบ Measurement ACK ได้ถูกต้อง ระบบรองรับการเก็บข้อมูลค้างใน NVS, ส่งใหม่หลังหลุดหรือรีสตาร์ต, ใช้ message_id เดิม และป้องกันคิวซ้ำด้วยสถานะ duplicate ได้แล้ว เหลือการยืนยันหน้าเว็บ สำหรับคิวล่าสุด การปรับ Backend Print Outbox และการทดสอบกับเซนเซอร์และเครื่องพิมพ์จริง
