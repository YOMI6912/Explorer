# ESP32-S3 Clinic - โครงสร้างแยกอุปกรณ์

เวอร์ชันนี้จัดโค้ดเป็นโมดูลตามอุปกรณ์แล้ว `main.cpp` จึงเหลือเฉพาะการเรียก
`begin()` ตอนเปิดเครื่อง และเรียก `update()`/ฟังก์ชันอ่านค่าใน `loop()`

รองรับคิว A ผ่าน OTP และคิว B แบบ Walk-in พร้อมเชื่อม EMQX Cloud ด้วย MQTT/TLS
สามารถทดสอบค่าจำลองผ่าน Serial Monitor ก่อนต่อ Load Cell, เซนเซอร์ส่วนสูง และ
เครื่องพิมพ์จริงได้

ขั้นตอนทดสอบร่วมกับ Backend และ MQTTX ดูได้ที่ `MQTT_TEST_GUIDE_TH.md`

## หน้าที่ของแต่ละส่วน

| ไฟล์ | หน้าที่ |
|---|---|
| `include/config.h` | ตั้งค่าขา, I2C, LCD, Keypad, HX711, VL53L1X, USB Printer และค่ารอใช้กับ MQTT |
| `src/main.cpp` | เรียกเริ่มต้นอุปกรณ์และเรียกฟังก์ชันอัปเดตเท่านั้น |
| `OnlineQueueWorkflow.*` | State machine ของคิว A, Wi-Fi/MQTT และคำสั่งทดสอบผ่าน Serial |
| `HX711Device.*` | เริ่ม HX711, อ่าน RAW, อ่านน้ำหนัก และตั้งศูนย์ |
| `VL53L1XDevice.*` | เริ่มเซนเซอร์, อ่านระยะ และคำนวณส่วนสูงเมื่อใส่ความสูงติดตั้งแล้ว |
| `KeypadDevice.*` | อ่าน Keypad I2C, แปลงบิตเป็นปุ่ม และ Debounce |
| `LcdDevice.*` | แสดงข้อความบน LCD 20x4 โดยจัดความยาวแต่ละบรรทัดให้พอดี |
| `UsbPrinter.*` | จัดการ USB Host, ตรวจ VID/PID และส่งข้อมูลไปเครื่องพิมพ์ |

## ค่าขาปัจจุบัน

| อุปกรณ์ | ค่าใน `config.h` |
|---|---|
| I2C SDA | GPIO8 |
| I2C SCL | GPIO9 |
| HX711 DT | GPIO4 |
| HX711 SCK | GPIO5 |
| LCD I2C | 0x27 |
| Keypad 4x4 ผ่าน PCF8574 | 0x20 (A0/A1/A2=0; ห้ามชน LCD 0x27) |
| VL53L1X I2C | ใช้ Address มาตรฐานของไลบรารี |
| USB Printer | VID 0x0FE6, PID 0x811E |

LCD, Keypad และ VL53L1X ใช้สาย I2C GPIO8/GPIO9 ชุดเดียวกันได้ เพราะมี I2C
Address ต่างกัน

## จุดที่ต้องตั้งค่าก่อนใช้ค่าจริง

1. `Config::LoadCell::CALIBRATION_FACTOR` ยังเป็น `1.0` จึงเหมาะสำหรับตรวจ
   RAW ก่อน ต้องเปลี่ยนเป็นค่าคาลิเบรตของ Load Cell ชุดจริงก่อนอ่านเป็น kg
2. `Config::HeightSensor::SENSOR_MOUNT_HEIGHT_CM` ยังเป็น `0.0` จึงอ่าน
   Distance ได้ แต่จะยังไม่คำนวณส่วนสูง ต้องใส่ความสูงจริงจากพื้นถึงเซนเซอร์
3. ถ้าไม่ต้องการเปิดอุปกรณ์บางตัว ให้เปลี่ยนค่าใน `Config::Features` เป็น
   `false`
4. ค่าเริ่มต้นไม่พิมพ์กระดาษทันทีที่เชื่อมต่อ ให้ใช้ `PRINTTEST` เมื่อต้องการลอง
   เครื่องพิมพ์ หรือเปลี่ยน `Config::Printer::PRINT_TEST_WHEN_CONNECTED = true`
   หากต้องการให้พิมพ์กระดาษทดสอบอัตโนมัติทุกครั้งที่พบเครื่องพิมพ์
5. ค่าลับ Wi-Fi/MQTT อยู่ใน `include/secrets.h` ซึ่งถูก `.gitignore` ไว้ หากย้าย
   โปรเจกต์ไปเครื่องใหม่ให้คัดลอก `include/secrets.example.h` แล้วกรอกค่าจริง
6. CA ของ EMQX ถูกฝังไว้ใน `include/emqx_ca.h` ห้ามเปลี่ยนเป็น `setInsecure()`

## วิธีทดสอบคิว A แบบไม่ต่ออุปกรณ์

Environment `esp32-s3-n16r8` ปิด LCD, Keypad, HX711, VL53L1X และ USB Printer
เพื่อทดสอบผ่าน Serial ส่วน `esp32-s3-hardware-test` เปิดอุปกรณ์จริงทั้งหมด ทั้งสอง
โหมดเปิดคำสั่ง Serial เพื่อทดสอบ OTP และค่าวัดกับ Backend/MQTT จริง

### 1. เตรียมโปรเจกต์เว็บ

1. ให้ผู้ดูแลเว็บเปิด Backend/Test environment และเชื่อม EMQX
2. รอการยืนยันว่า Backend Subscribe `clinic/v1/devices/+` สำเร็จ
3. ขอ OTP ใหม่สำหรับอุปกรณ์ `SCALE-001` เมื่อต้องการทดสอบคิว A
4. ถ้าต้องการทดสอบ Print Job ให้เปิดและเข้าสู่ระบบหน้า Admin Dashboard ค้างไว้

### 2. เตรียม ESP32-S3

1. ตรวจ Wi-Fi และ MQTT password ใน `include/secrets.h`
2. ESP32 ต้องออกอินเทอร์เน็ตและติดต่อ EMQX hostname ที่ port `8883` ได้
3. ปิด Serial Monitor เดิมก่อน Upload เพื่อไม่ให้พอร์ต COM ถูกใช้งานค้าง
4. กด Build และ Upload
5. เปิด Serial Monitor ที่ `115200 baud` และเลือก Line Ending เป็น `Newline`
6. รอข้อความ `[Wi-Fi] เชื่อมต่อสำเร็จ` และ
   `[MQTT] เชื่อมต่อ TLS สำเร็จและ Subscribe Topic ครบแล้ว`
7. พิมพ์ `สถานะ` แล้วกด Enter เพื่อตรวจอีกครั้ง

### 3. สร้างคิวและ OTP สำหรับทดสอบ

1. ในโฟลเดอร์ `backend` รัน `npm.cmd run tool:patients`
2. เลือกเมนู `4` เพื่อสร้างคนไข้ นัดหมาย คิว A และ OTP แบบรวดเร็ว หรือเลือก
   เมนู `3` เพื่อสร้างคิวให้คนไข้ทดสอบที่มีอยู่
3. Tool จะแสดงคำสั่งลักษณะ `T 176023 60 170`
4. OTP ใช้ได้ครั้งเดียวและมีเวลาหมดอายุ จึงควรใช้รหัสล่าสุดเสมอ

### 4. ทดสอบแบบอัตโนมัติ

คัดลอกคำสั่ง `T` ที่ Tool แสดงมาวางใน Serial Monitor แล้วกด Enter เช่น:

```text
T 176023 60 170
```

หรือใช้คำสั่งภาษาไทยที่ให้ผลเหมือนกัน:

```text
ทดสอบ 176023 60 170
```

ผลที่ควรเห็นตามลำดับ:

1. `[อัตโนมัติ] ขั้นที่ 1/2 กำลังตรวจสอบ OTP`
2. `[OTP] ยืนยันสำเร็จ พร้อมรับค่าวัดของคิวออนไลน์`
3. `[อัตโนมัติ] ขั้นที่ 2/2 กำลังส่งน้ำหนักและส่วนสูงจำลอง`
4. `[ACK] Backend บันทึกค่าวัดสำเร็จ`
5. `[ACK] หมายเลขคิว: Axxx`

### 5. ทดสอบแบบแยกขั้นตอน

ส่ง OTP จริงก่อน โดยเลือกใช้คำสั่งใดคำสั่งหนึ่ง:

```text
A 176023
```

```text
คิวเอ 176023
```

เมื่อเห็นข้อความว่า OTP ยืนยันสำเร็จ ให้ส่งค่าวัดจำลอง:

```text
วัด 60 170
```

Firmware จะส่ง `measurement_session_id`, น้ำหนัก และส่วนสูงไป Backend โดยไม่มี
BMI และไม่สร้างหมายเลขคิวเอง

### 6. คำสั่ง Serial ภาษาไทย

| คำสั่ง | การทำงาน |
|---|---|
| `ช่วยเหลือ` หรือ `?` | แสดงรายการคำสั่ง |
| `สถานะ` | แสดงสถานะ Wi-Fi, MQTT, IP และขั้นตอนปัจจุบัน |
| `คิวเอ 123456` | ส่ง OTP จริง 6 หลักไปตรวจสอบ |
| `วัด 60 170` | ส่งน้ำหนัก 60 kg และส่วนสูง 170 cm หลัง OTP ผ่าน |
| `ทดสอบ 123456 60 170` | ตรวจ OTP และส่งค่าวัดให้อัตโนมัติ |
| `W 60 170` | ส่งค่าวัดจำลองแบบ Walk-in และรอเลขคิว B โดยไม่ใช้ OTP |
| `A123456#` | จำลอง Keypad: กด A, กรอก OTP และกด # |
| ปุ่ม `B` บน Keypad | ตอนว่างส่ง Walk-in; หลัง OTP ผ่านส่งค่าวัดคิว A |
| `พิมพ์ทดสอบ` หรือ `PRINTTEST` | ส่งกระดาษทดสอบไปเครื่องพิมพ์ USB จริง |
| `C` | ลบเลข OTP ตัวล่าสุดในโหมดจำลอง Keypad |
| `D`, `*` หรือ `ยกเลิก` | ล้างขั้นตอนใน ESP32 และกลับหน้าเริ่มต้น |

คำสั่งเดิม `HELP`, `STATUS`, `CANCEL`, `A`, `M` และ `T` ยังรองรับ เพื่อให้ใช้
ร่วมกับ Clinic Test Patient Tool และ Keypad จริงในภายหลังได้

### 7. การทดสอบกรณีผิดพลาด

- OTP ผิด หมดอายุ ถูกใช้แล้ว หรือเป็นของคิวที่ยกเลิก: ต้องแสดงสาเหตุและไม่ส่ง
  น้ำหนัก/ส่วนสูง
- ส่ง `วัด 60 170` ก่อน OTP ผ่าน: ต้องแจ้งว่ายังไม่มี
  `measurement_session_id`
- น้ำหนักน้อยกว่า 1 หรือเกิน 300 kg: ต้องไม่ส่ง
- ส่วนสูงน้อยกว่า 30 หรือเกิน 250 cm: ต้องไม่ส่ง
- พิมพ์ `ยกเลิก`: ล้างเฉพาะขั้นตอนใน ESP32 ไม่ได้ยกเลิกนัดใน Backend

เมื่อ Backend ส่ง Print Job กลับมา โปรแกรมจะแสดงตัวอย่างใน Serial เสมอ ถ้าเลือก
โหมดอุปกรณ์จริงและเครื่องพิมพ์พร้อม จะพิมพ์บัตรคิวแล้วตอบ `print-ack` เป็น
`printed` หลัง USB transfer สำเร็จจริง หากยังไม่พบเครื่องพิมพ์จึงตอบ `failed`
พร้อม `PRINTER_NOT_CONNECTED` ส่วนโหมดไม่ต่ออุปกรณ์จะไม่พิมพ์กระดาษ

## ทดสอบอุปกรณ์จริงรอบแรก (Hardware Diagnostics)

โปรเจกต์มี Environment `esp32-s3-hardware-test` สำหรับเปิด LCD, Keypad,
HX711, VL53L1X และ USB Printer พร้อมกัน โดย Environment เดิม
`esp32-s3-n16r8` ยังคงเป็นโหมดไม่ต่ออุปกรณ์

### การต่อสาย

ปิดไฟ ESP32 และแหล่งจ่ายของอุปกรณ์ก่อนต่อหรือถอดสายทุกครั้ง

| อุปกรณ์ | การต่อกับ ESP32-S3 |
|---|---|
| LCD 20x4 I2C | SDA=GPIO8, SCL=GPIO9, GND ร่วม และใช้ไฟ/Level ที่ปลอดภัยกับลอจิก 3.3V |
| Keypad 4x4 ผ่าน PCF8574 | VCC=3.3V, SDA=GPIO8, SCL=GPIO9, Address=0x20, GND ร่วม; ห้ามตั้งเป็น 0x27 เพราะชนกับ LCD |
| VL53L1X | SDA=GPIO8, SCL=GPIO9, ใช้ไฟ 3.3V และ GND ร่วม |
| HX711 | DT=GPIO4, SCK=GPIO5, VCC=3.3V, GND ร่วม; Load Cell ต่อ E+/E-/A+/A- ตามป้ายบนบอร์ด |
| WINMAX-8032 | ใช้แหล่งจ่ายของเครื่องพิมพ์เอง และต่อสายข้อมูลเข้าพอร์ต USB OTG/Host ของ ESP32-S3 |

ห้ามจ่ายไฟมอเตอร์หรือไฟเลี้ยงเครื่องพิมพ์จากขา 3.3V/5V ของ ESP32 และหาก
LCD Backpack ดึง SDA/SCL ขึ้น 5V ต้องใช้ตัวแปลงระดับสัญญาณหรือย้าย Pull-up
ไป 3.3V ก่อนต่อกับ ESP32-S3

### Build และ Upload

วิธีง่ายที่สุดคือดับเบิลคลิก `SELECT_ESP32_MODE.bat` แล้วเลือก:

- `1` เปิดและ Upload โหมดอุปกรณ์จริง
- `2` กลับไปโหมดไม่ต่ออุปกรณ์และใช้ Serial จำลอง

กรอก COM port เช่น `COM19` หรือกด Enter ให้ PlatformIO ค้นหาให้อัตโนมัติ
เมนูจะแสดงรายการ Serial ที่ตรวจพบก่อนถามพอร์ต และต้องปิด Serial Monitor เดิม
ก่อน Upload หาก Build/Upload ไม่สำเร็จหรือหยุด Serial Monitor แล้ว โปรแกรมจะ
กลับมาถามโหมดใหม่อัตโนมัติ ไม่ตกค้างที่ Command Prompt

ใน PlatformIO เลือก Environment `esp32-s3-hardware-test` แล้วกด Upload หรือรัน:

```powershell
pio run -e esp32-s3-hardware-test -t upload
pio device monitor -e esp32-s3-hardware-test
```

เปิด Serial Monitor ที่ 115200 baud โดยรอบแรกควรเห็น:

```text
[I2C] SDA=GPIO8 SCL=GPIO9 Clock=100000 Hz
[LCD] Ready
[KEYPAD] Ready
[HX711] Ready
[VL53L1X] Ready
[PRINTER] Waiting for configured USB printer...
```

เมื่อกด Keypad ต้องเห็น `[Keypad] กดปุ่ม: ...` ค่า HX711 จะแสดงเป็น `RAW`
และ VL53L1X จะแสดง `Distance=... mm` ทุก 500 ms เครื่องพิมพ์ที่ VID/PID ตรงกับ
`config.h` จะแสดง `[PRINTER] WINMAX-8032 ready` โดยไม่พิมพ์กระดาษเอง หากต้องการ
ตรวจเครื่องพิมพ์แยก ให้พิมพ์ `พิมพ์ทดสอบ` ใน Serial Monitor

หลัง OTP ผ่าน สามารถกด `B` เพื่ออ่านน้ำหนักและส่วนสูงจริงแล้วส่ง Backend ได้ แต่
ต้องคาลิเบรต `CALIBRATION_FACTOR` และตั้ง `SENSOR_MOUNT_HEIGHT_CM` ก่อน ค่าเริ่มต้น
`1.0` และ `0.0` มีไว้ให้วินิจฉัยอุปกรณ์ จึงยังไม่ใช่หน่วยจริง หากต้องการทดสอบระบบ
ครบเส้นทางก่อนคาลิเบรต ให้ใช้ `วัด 60 170` แทนค่าจากเซนเซอร์

### ทดสอบคิว A กับ Keypad และเครื่องพิมพ์จริง

1. ให้ผู้ดูแลเว็บเปิด Backend และ MQTT พร้อมทำงาน และเปิด/เข้าสู่ระบบหน้า Admin
   Dashboard ค้างไว้เมื่อต้องการให้ระบบคำนวณ BMI และส่งงานพิมพ์
2. ที่หน้าต่าง ESP32 เลือก `1` แล้วเลือก COM ของบอร์ด รอให้ Serial แสดงว่า Wi-Fi,
   MQTT และเครื่องพิมพ์เชื่อมต่อสำเร็จ
3. ใน Clinic Test Patient Tool เลือกเมนู `4` เพื่อสร้างคนไข้ คิว A และ OTP ใหม่
4. ที่ Keypad กด `A` ตามด้วย OTP 6 หลัก แล้วกด `#`
5. เมื่อเห็น `[OTP] ยืนยันสำเร็จ` ให้ยืนนิ่งแล้วกด `B` หากคาลิเบรตเซนเซอร์แล้ว
   หรือพิมพ์ `วัด 60 170` ใน Serial เพื่อทดสอบด้วยค่าจำลอง
6. รอ `[ACK] Backend บันทึกค่าวัดสำเร็จ` และหมายเลขคิว `Axxx` จากนั้น Backend
   จะส่ง Print Job ทันที เครื่องพิมพ์ต้องออกบัตรและ Serial ต้องแสดง
   `ACK=printed` พร้อม `print_job_id` ที่ไม่ว่าง
